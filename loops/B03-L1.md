# B03-L1 — Profile required fields (name/birthdate/gender)

**Backlog:** B03 (PRD §12) · **Loop:** L1 · **Date:** 2026-07-19
**Previous loop:** none

## Plan (post-grill)

Require name/birthdate/gender before using the app, enforced by a blocking
onboarding gate. **Storage stays localStorage** (grill decision) — no DB, no
migration, no server fn. B04 owns body measurements; B07 will migrate profile
to a real account later. Birthdate = native `<input type="date">`.

- **Type/helper** `src/hooks/use-profile.ts`: add `birthdate: string` (ISO `yyyy-mm-dd`, default `""`) to `Profile` + `DEFAULT_PROFILE`; export `isProfileComplete(p)` = `name.trim() !== "" && gender !== "" && birthdate valid` (non-empty, parseable, not in the future).
- **Birthdate field** in `EditProfileModal.tsx`: native `<input type="date" max={today}>` in the "ข้อมูลพื้นฐาน" section; wired into draft + save patch.
- **Validation** on `EditProfileModal` save: name non-empty (exists), gender ≠ `""`, birthdate present + not future — block save + toast the specific missing field.
- **Gate** NEW `src/components/ProfileGate.tsx`: slim non-dismissable modal with just the 3 required fields; save enabled only when all valid. Mounted in `__root.tsx` `RootComponent` around `<Outlet/>`. Renders only after client mount (guard SSR/hydration — DEFAULT_PROFILE is incomplete on the server, so must not flash the modal during SSR).
- No reuse of the full `EditProfileModal` for the gate (it has avatar/handle/email/bio — too heavy for onboarding).
