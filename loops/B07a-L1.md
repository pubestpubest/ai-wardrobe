## Scrutinize findings

_(Opus, fresh, security-weighted. Verified sound end-to-end: RLS `auth.uid()=user_id` (read+write); `user_id` server-derived + unforgeable (zod strips it, upsert hardcodes `context.userId`, RLS `with check` backstops); no service-role touches `profiles`; token→identity path; SSR gating leaks nothing; PIN validated + never logged; guardrails (011 additive, items/matches/body untouched). Verdict: fix-then-ship.)_

- **gate-stage** — AuthGate `mounted`-guard wrapped `<Outlet/>` → whole app stopped SSR-ing — **fixed** (sent back to implementer; renders children on SSR, login after mount)
- **major** (defense-in-depth) — profile query key static `["profile"]`; cross-user isolation relied on `queryClient.clear()` on logout, not cache structure (no live exploit, but fragile) — **fixed here** (`queryKey: ["profile", session.user.id]` → account switch can't serve a stale profile)
- **minor** — ProfileGate `isLoading` guard missed the auth-loading window (query disabled pre-session → `isLoading` false) → onboarding modal could flash for a returning user — **fixed here** (guard on `authLoading || !session`)
- nit — no length/birthdate caps on `upsertProfile` fields (client already constrains; RLS scopes to self) — **deferred**
- nit — duplicate `useAuth()` subscriptions (AuthGate/useProfile/profile.tsx) — **deferred** (shared context if it grows)
