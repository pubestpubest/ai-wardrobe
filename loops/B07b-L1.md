# B07b-L1 — Scope items to user_id

**Backlog:** B07b (PRD §12, under B07) · **Loop:** L1 · **Date:** 2026-07-19
**Previous loop:** none (B07a-L1 is the prior B07 slice)

## Plan (post-grill)

Second B07 slice: make wardrobe items per-user (RLS), same pattern as B07a.
Grilled backfill (2026-07-19): **one-time claim action** — user_id stays
nullable, RLS hides orphans, a service-role `claimOrphanItems` fn (button on
profile) assigns NULL-user rows to the caller. Reverses migration 003's open
items policy (authorized under the B07 human go).

- **Migration `012_scope_items.sql`**: drop the `items` "Guest mode — open" policy; create RLS `auth.uid() = user_id` (select/insert/update/delete, `pg_policies` guard idiom). `user_id` **stays nullable** (orphans just become invisible — no data loss, no NOT NULL failure). No row deletes.
- **`src/lib/items.functions.ts`**: all of getItems/saveItem/updateItem/removeItem/wearItem get `.middleware([requireSupabaseAuth])` and use the **user-scoped `context.supabase`** instead of `adminClient()`. `saveItem` writes `user_id: context.userId`. update/delete/wear keep `.eq("id", …)` — RLS now enforces ownership, closing the id-only-delete hole for free. `removeItem`: DB delete via user-scoped client (RLS), storage file removal via a service-role admin client (storage = admin op).
- **`claimOrphanItems`** (new, in items.functions.ts): `.middleware([requireSupabaseAuth])`, uses **service-role** admin (must, since RLS hides NULL rows from the user client) to `update items set user_id = context.userId where user_id is null`; returns count.
- **`src/hooks/use-wardrobe.ts`**: gate the items query `enabled: !!session` and scope the query key to `session.user.id` (mirror the B07a fix — no cross-user cache leak, no SSR/logged-out call to the now-auth-required fn).
- **`src/routes/profile.tsx`**: "อ้างสิทธิ์ไอเท็มเดิม" button → `claimOrphanItems` → toast count + invalidate wardrobe.

**Out of scope (noted):** `wardrobe-images` bucket is still public (world-readable by URL) — privatizing needs signed-URL rework; separate follow-up. Matches/body-model are B07c.

Verdict: fix-then-ship.)_

- **blocker (IDOR, confirmed)** — `removeItem` deleted a **client-supplied** `imageUrl` via service-role with no ownership check → any user could delete any file in `wardrobe-images` by URL — **fixed here** (drop `imageUrl` from input; derive path from the caller's own row via RLS-scoped `context.supabase`; non-owner → no-op)
