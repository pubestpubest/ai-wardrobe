# B07d — Per-user AI quota

**Backlog:** B07d (PRD §12, under B07) · **Loop:** L1 · **Date:** 2026-07-19
**Previous loop:** B07c-L1 (last B07 slice)

## Plan (post-grill)

Server-enforced daily AI-call quota per user. The two real Gemini calls
(`matchChat`, `analyzeClothing`) are currently unauthenticated → add
`requireSupabaseAuth` so they know the user, then meter. Mock try-on/body-model
make no AI call → excluded.

**Grilled:** per-type daily caps — **chat 30/day, auto-tag 20/day** (chat ≥5
satisfies §3.1); **hard block** with a friendly Thai message at the cap.

- **Migration `015_ai_usage.sql`**: `ai_usage(user_id uuid references auth.users, usage_date date, kind text, count int, primary key (user_id, usage_date, kind))` + RLS `auth.uid()=user_id`. Plus an **atomic** `bump_ai_usage(p_kind text) returns int` SQL function (`security invoker`) that `insert … on conflict (user_id,usage_date,kind) do update set count = count+1 returning count` for `auth.uid()`/`current_date` — race-safe reserve-a-slot (no TOCTOU). Limits live in app code, not the DB.
- **`src/lib/ai-quota.ts`** (new): `enforceAiQuota(supabase, kind, limit)` → `supabase.rpc("bump_ai_usage", { p_kind: kind })`; if returned count > limit, throw a friendly Thai quota error. Reserve happens before the AI call (a blocked/failed attempt still counts — correct for cost).
- **`match-chat.functions.ts`**: add `.middleware([requireSupabaseAuth])`; `await enforceAiQuota(context.supabase, "chat", 30)` before the Gemini call.
- **`analyze.functions.ts`**: add `.middleware([requireSupabaseAuth])`; `await enforceAiQuota(context.supabase, "analyze", 20)` before the Gemini call.
- **Client**: `StylistChat.tsx` + `UploadItem.tsx` already `toast.error((err).message)` — the friendly quota message propagates; verify it reads well, minimal change.

**Reset:** server `current_date` (UTC — resets ~07:00 Thailand). Acceptable; noted.
