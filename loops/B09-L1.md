# B09-L1 — Background removal

**Backlog:** B09 (PRD §12 "awaiting decision" / Open Question 9.5) · **Loop:** L1 · **Date:** 2026-07-19
**Previous loop:** none

## Plan (post-grill)

Resolves Open Question 9.5 (which bg-removal vendor). Grilled decision:
**`@imgly/background-removal`, client-side, free** — runs in-browser (ONNX+WASM),
no API key, images stay on-device, so preview-and-reject attempts cost nothing.
UX: **preview + opt-in** (user decides to keep the cutout or the original — bad
cutouts on tricky images shouldn't silently ruin the photo).

- **Dependency**: `bun add @imgly/background-removal` (AGPL — fine pre-commercial; revisit license if closed-source commercial). New npm dep authorized by the grill.
- **UX in `UploadItem.tsx`** (client-only): after an image is picked (existing `fileToCompressedDataUrl` step), add a **"ลบพื้นหลัง"** button. On click: loading state → `removeBackground(previewDataUrl)` → set preview to the returned **transparent PNG** cutout, keep the original in state → show a **"ใช้รูปเดิม"** (revert) so the user picks. Whatever `preview` holds at save is uploaded.
- **Client-only import**: `const { removeBackground } = await import("@imgly/background-removal")` inside the handler (keep WASM/browser code out of SSR + the main bundle).
- **Model assets**: default IMG.LY CDN. If the app CSP blocks it, self-host via `config.publicPath` (follow-up, note in doc).
- **PNG storage**: the cutout is a PNG data URL (has alpha). Confirm `uploadWardrobeImage` (`upload.functions.ts`) stores it with the correct content-type (not forced JPEG). Transparent cutout renders on the tinted `WardrobeCard` tones.
- **No migration, no server fn, no API key.** AI auto-fill + save flow unchanged otherwise.

**Risks to watch (for gate/scrutinize):** SSR-safety of the dynamic import; model load failure / CSP; large images + on-device compute time (loading UX); PNG round-trip through upload.

## Implemented

- `package.json` — `@imgly/background-removal@^1.7.0` (`bun add`)
- `src/components/UploadItem.tsx` — "ลบพื้นหลัง" button (dynamic `import()`, client-only) → cutout preview on checkerboard + "ใช้รูปเดิม" revert; `original`/`isCutout`/`bgRemoving` state; loading copy; `blobToDataUrl` helper; reset clears state
- `src/lib/upload.functions.ts` — derive extension from mime (`image/png`→`.png`) so the PNG cutout round-trips (content-type was already from mime)
