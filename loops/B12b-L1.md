## Plan (post-grill)

1. **`supabase/migrations/022_store_update_grant.sql`**

   ```sql
   grant update (name, description, contact_phone, contact_line, contact_email,
                 address, google_map_url, online_store_url, logo_url, cover_url)
     on public.stores to authenticated;
   ```

   Column-level only. **`owner_user_id` is deliberately NOT in the UPDATE list**
   (insert-only in `020`) — an owner must not be able to hand their store to
   another account. `package`/`status`/`id`/`created_at` stay ungranted, so the
   B11 escalation stays closed.

   `021`'s CHECK constraints already apply to UPDATE as well as INSERT, so the
   http(s)-only URL rule, the non-blank name, the description cap and the
   at-least-one-contact rule all bound the edit path too. **That is the whole
   reason `021` exists** — B12a-L2 proved zod alone doesn't bound values once a
   caller holds the grant. Verify this in the gate rather than assuming it.

2. **`updateStore` in `src/lib/store.functions.ts`** — behind
   `requireSupabaseAuth`, writing through `context.supabase` so RLS
   `Owners manage own store` enforces ownership. Reuse the existing zod field
   shapes (`httpUrl`, the ≥1-contact refine). Never accepts `ownerUserId`,
   `package` or `status`.

3. **`/store`** — store profile editor (name, description, contacts, address,
   map, online shop, logo, cover). Renders the **registration form** when the
   caller has no `stores` row, so neither a `role='store'` account with a failed
   registration nor a shopper who wanders in hits a dead end (`LOCAL-STORE.md`
   §2).

4. **`/store/package`** — the บัญชี tab: current package + its limits from
   `STORE_PACKAGES`, item quota (`n/maxItems`, counted from `affiliate_products`
   for this store — the seeded shops already have 18/12/9/5/4/2 so this shows
   real numbers immediately), a "ติดต่อเพื่ออัปเกรด" contact affordance (packages
   are admin-assigned, no self-serve — `LOCAL-STORE.md` §7), the account email,
   and ออกจากระบบ.

5. **`StoreBottomNav`** — ร้านค้า (`/store`) · ไอเท็ม (disabled, "เร็ว ๆ นี้") ·
   บัญชี (`/store/package`). No โปรไฟล์ tab: a shop has no personal profile, the
   store profile _is_ tab 1, and `/profile` is unreachable under the guard below.

6. **`__root.tsx` redirect guard** — one guard beside the existing gates:
   `role === 'store'` and pathname outside `/store` → redirect to `/store`.
   **Must wait for the profile query to resolve**: `useProfile` returns
   `DEFAULT_PROFILE` (`role: 'shopper'`) before it loads, so redirecting eagerly
   would flash the shopper home to every store owner on every navigation.

7. **Replace B12a's success panel** on `/store/register` with a redirect to
   `/store`, now that there is somewhere to land.

Out of scope: `/store/items` (B13), Discover store cards and `/store/$id` (B14),
AI weighting (B15), admin package/suspend (B16).

## Gate

lint ✅ (0 errors, 2 react-refresh warnings) · build ✅ · tsc 7 = baseline ✅ ·
migration ✅ · renders — **❌ see findings**

Pen-tested the UPDATE path live as `lungchat@store.test` via direct PostgREST.
The discriminating case is the first: RLS's `with check` would also reject an
`owner_user_id` change and would therefore MASK a wrong grant, so only a
GRANT-level denial proves the column is excluded.

| PATCH                           | Result                        |
| ------------------------------- | ----------------------------- |
| `owner_user_id` → other account | **GRANT-denied** (not RLS)    |
| `package` → premium             | GRANT-denied                  |
| `status` → approved             | GRANT-denied                  |
| `javascript:` `logo_url`        | CHECK `stores_urls_http_only` |
| clear every contact channel     | CHECK `stores_has_contact`    |
| blank name                      | CHECK `stores_name_not_blank` |
| edit another store              | 0 rows (RLS)                  |
| own description                 | 1 row                         |

`021`'s CHECKs demonstrably bound the UPDATE path, rather than that being assumed.
