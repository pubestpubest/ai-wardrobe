## Why this loop exists

### MAJOR — a failed fetch is indistinguishable from "you have no store"

`use-store.ts` destructured only `{ data, isLoading }`; `isError` was never
surfaced. `router.tsx` uses a bare `new QueryClient()`, so `retry: 3` applies and
then gives up.

Authenticated owner hard-loads `/store/package` → `session` is truthy so L2's
`!session ||` guard is inactive → `getMyStore` throws → retries exhaust →
`store === null`, `isLoading === false` → the no-store branch fires →
`/store/package` redirects to `/store`, which renders **`สมัครร้านค้า`** to a real
owner. The exact L1 symptom, reached through a different door.

L2 _widened_ the trigger: `getMyStore` now runs a second query (the
`affiliate_products` count) whose error collapses the whole result to "no store".

### NIT — `toRow`'s justification was wrong on the wire

The comment said "safe because `StoreForm` always sends all ten". It doesn't —
`toStoreInput` emits `undefined` for empty inputs and JSON drops those keys. It's
safe because the edit form seeds its draft from the fully-loaded store, so an
omitted field means the user genuinely cleared it. Conclusion held, reason didn't.
